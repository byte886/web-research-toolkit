# 网络分流与检索语言策略（network-and-language）

> 本文管两件事：① 检索语言怎么选（先英后中/按信息生态选源）；② 海外 AI 搜索 API 的选型定位。选哪个取数通道见 `channel-selection.md`，逐通道边界见 `channels-detail.md`。

## 4.1 检索语言策略：选源看内容生态，召回"先英后中"

### A. 按内容语言/生态选源（与"能不能连上网"是两回事）

- **中文 / 国内内容**（gov.cn、国内政策与市场、中文媒体）：内置联网搜索 + 垂直库 + web.fetch 为主，对国内生态覆盖最好。
- **英文 / 海外内容**（海外公司、国际市场、英文文献与资料）：内置搜索对英文网页覆盖有限；需要时开代理用 Google，或接入下面的海外搜索 API。

### B. 检索语言跟着"信息源的原生语言"走：多语召回，优先 ≠ 放弃

核心不是"一律先英文"，而是先判断**这批信息主要以哪种语言生产、沉淀**，就以那种语言为主去搜；然后通常再补一轮其它语言，合并去重、交叉核验，而不是只用问题的原语言、也不是只搜一种语言。

- **以英文为主**：软件开发/编程/报错、开源库与工具、AI/算法/论文、工程实践、国际产品与公司、协议标准/RFC、国外领先领域——一手资料、最新进展、问答沉淀主要是英文。**报错信息、异常栈、API 名、型号/版本号原样用英文搜，不要翻译**（翻译反而降低命中率）。
- **以中文为主**：国内业务与本土生态——中国房产/土地/资产评估、国内政策法规与红头文件、A 股/港股中文研报、本土平台（微信/抖音/B站/小红书/淘宝/12306）、地名/本地机构/本地生活、中文专有语境。例如做国内房产评估研究，信源就是中文为主。
- **配目标源语言（不止中英）**：研究某国/某语种市场就配该语种——日本市场用日语、德语区用德语、韩国用韩语；把关键术语译成该语种后按原语种检索，再用中/英交叉核验。
- **优先不等于放弃**：定了主语言后，一般仍补一轮次语言——英文为主时补中文看国内实践/中文教程与踩坑；中文为主时补英文看国际方法论、可比案例、技术底座——两边合并去重、交叉验证；只有能确定次语种确实无增量（纯本地办事流程、中文红头文件、本土独家信息）时才省掉。
- 拿不准归属时中、英各搜一轮（成本很低）；外文 query 用"专业术语 + 具体报错/型号/版本号"命中率最高，避免口语化整句直译。

口诀：代理只解决"能不能连上"（连通性），检索语言决定"索引全不全、新不新、对不对口"（召回率与相关性）；主语言由信息生态决定（技术/国际前沿→英，国内业务→中，特定国别→该语种），次语言作补充而非放弃。

## 4.2 海外 AI 搜索 API（扩展位：当前未接入，需自备 key、多数付费）

按"搜索停在哪一步"分工；价格随官方调整，接入前以官网为准，此处只记定位、不写死价格。

| 工具 | 停在哪步 / 定位 | 典型用途 |
| --- | --- | --- |
| Tavily | 搜索 + 干净正文，最均衡的默认项 | 海外市场/竞品调研、RAG 事实采集 |
| Exa | 语义/神经检索，"给一个找一批相似" | 同类发现、概念/公司发现 |
| Perplexity Sonar | 直接返回带引用的答案（按 token 计费） | 一步到位问答 |
| Brave | 独立索引，不依赖 Google/Bing | 隐私/独立索引备选 |
| Serper/SerpAPI | 只取 Google SERP 原始结果 | SEO/排名追踪，成本最低 |
| Firecrawl | 搜索后整站批量爬取 + 结构化 | 批量内容获取（本技能已接 keyless 单页） |

> 选型：90% 海外检索默认 Tavily；要"找相似"用 Exa；整站批量用 Firecrawl；想直接拿答案用 Sonar；Brave/Serper 为备选。真要接入某个时再单独出接入与成本方案。
