# 生财有术 MCP（scys-mcp）取数指南

> 付费社群「生财有术」站内检索/精读/个人数据/AI 亦仁的专用通道。本文件是 web-research-toolkit 的一个**取数通道参考**：当目标信息长在生财有术站内（精华帖、风向标、项目库、航海手册、圈友发言、线下局、个人足迹）时读本文件；公开网络信息仍走 SKILL.md 的通用通道。
>
> 平台与验证：连接器走 HTTP，本身与操作系统无关；下列配置、参数与坑在 **macOS 豆包桌面端实测**（安装/连通 2026-09-09 验证，大规模调研管线 2026-09 验证）。换平台时连接配置不变，豆包入口位置以实际客户端为准。

## 1. 定位：什么时候用它

接上 scys-mcp 后，背后模型还是同一个，**通用智商/文笔不变，变的是「眼」和「手」**：能读到会员才可见的站内真实数据并带原文链接（眼），能以用户身份执行只读/写动作（手）。

先判断问题类别，再决定是否走本通道：

| | A 类：要用到生财内部信息或动作 | B 类：纯通用能力 |
| --- | --- | --- |
| 典型 | 搜某主题精华帖、读航海手册、查项目库真实案例、看某圈友多年发言、查自己足迹/积分、找线下局 | 教写作、起标题、通用商业计划 |
| 裸豆包 | 做不到，公开网没有这些私有数据，硬答=编造 | 能用训练知识答 |
| 挂 scys-mcp | 质变：拿到权限内真实数据+原文出处，可溯源 | 文笔本身无差别，差别只在「用什么料」 |

口诀：**通用问题不必走本通道；凡答案需要「生财里有什么、谁做过、原文怎么说」就必须先搜再生，模型不会默认去搜。**

## 2. 安装、授权与连通性自检

一次性配置（换机/帮他人安装照填，2026-09-09 实测）：

| 配置项 | 值 |
| --- | --- |
| 入口 | 豆包桌面端「技能·连接器·伙伴」→ 新建自定义连接器，命名 `scys-mcp` |
| 服务地址 | `https://mcp.scys.com/shengcai-web/mcp` |
| 传输方式 | HTTP（Streamable HTTP） |
| 授权 | OAuth 2.1 + PKCE，点「去授权」后浏览器用生财账号（微信快捷登录）确认，**无需手填 Token** |
| 启用 | 对话输入框上方「连接器」里勾选 scys-mcp；连接器共约 45 个工具，按授权暴露 |
| 前提 | 需有效的生财有术会员账号；只能看到该账号权限内的内容（深海圈、航海手册按是否加入/购买返回） |

连通性自检（安装后或怀疑掉线时做，只读、无参、最轻量）：
1. 调用前若该工具 schema 不在当前上下文，**先用 tool_search 按精确名取 schema，禁止凭记忆拼参数**。
2. 调 `listMenu`（无参数）：成功返回站内常用标签/菜单即连通；返回登录/授权超时才判定为凭证问题（这是最后怀疑项，先排查工具是否勾选、参数是否正确）。

## 3. 工具地图与高频工具参数

45 个工具按 8 能力域理解：① 内容搜读 ② 航海陪跑（手册 SOP/领航/关卡/船员作业）③ 项目库（按资金/时间/方向筛真实案例）④ 找人研究人（圈友主页、关注关系、人物画像）⑤ 线下聚会（城市/主题局、组局官、报名）⑥ 个人数据（足迹、龙珠术值、我的航海产出、用量榜、AI 问答史）⑦ 社区写操作（点赞/收藏/投锚/关注，默认不自动执行）⑧ AI 亦仁与情报。

工具调用名前缀 `mcp__scys_mcp__`；**以下为大规模调研高频且实测过的工具，参数以 tool_search 取回的真实 schema 为准**：

| 工具 | 作用 | 关键入参 / 返回要点 |
| --- | --- | --- |
| `listMenu` | 列站内常用标签/菜单，兼作连通性测试 | 无参 |
| `contentSearch` | 全站/分区搜帖，**主力广搜** | `pageScene=all`、`keyword`、`pageIndex` 从 **1** 开始、`pageSize` 上限 **50**、`displayMode=1` |
| `searchTopic` | 话题维度兜底搜索 | `pageSize` 上限 **10**；contentSearch 漏检时补 |
| `topicDetail` | 读单帖全文与统计 | 入参 `entityType`+`entityId`（帖子均为 `entityType=xq_topic`） |
| `activitySearch` / `activityPilotSearch` | 搜航海/活动及其领航 | 项目库、航海陪跑场景 |
| `getProfileInfo` | 圈友公开主页 | 研究人/人物画像 |
| `listMyTopicFootprints` | 自己的浏览足迹 | 个人数据 |
| `ai_listAiFeedItems` | AI 情报流 | 情报订阅 |
| `searchMyActivityOutputs` | 我的航海产出/作业 | 个人数据 |
| `startAiYiRenChat` / `queryAiYiRenChat` | AI 亦仁：发起提问 / 轮询取答（工具名以实际暴露为准，当前会话或显示为 `startaiyirenchat`） | 见第 6 节 |

`topicDetail` 返回字段怎么读（省 token 的关键）：
- `aiSummaryContent`：现成 HTML 要点摘要，**深读首选**，够用就不读全文。
- `articleContentContainFeishuDoc`：飞书文档被展开的纯文本全文，精华长文主要读它。
- `articleContent`：常只有简介+飞书链接，信息不全时别误当全文。
- `menuList`（标签）、`likeCount/commentCount/favoriteCount/readingCount`（互动）、`topicUserDTO`（作者）。
- 帖子 URL 规律：`https://scys.com/articleDetail/xq_topic/<entityId>`，交付时用它拼可溯源原文链接。

## 4. 付费社区主题调研标准管线（SOP）

对「把某主题在生财站内一次性调研透」按序执行，每步落盘、可复算：

1. **界定**：子问题、交付形态（结论/数据集/报告/知识库）、时间与分区口径。
2. **广搜拉全**：`contentSearch` 用主题词及同义词逐页翻（`pageSize=50`、`pageIndex` 从 1 递增到无结果），`searchTopic` 兜底；**每页当轮就落盘**，不要多页结果堆在同一轮（见 §5）。
3. **全局去重**：按 `entityId` 去重，记录去重前后量级。
4. **相关性过滤**：用标题（必要时加摘要）剔除「只蹭词、实际不相关 / 擦边 / 不重大」的噪声；拿不准的边界条目单独列出、人工判一遍再决定救回或删除，避免误杀。
5. **多维分类**：用规则脚本给每篇打固定维度标签（如平台、品类、创业阶段、内容类型、产业带、互动量级、是否精华），导出 CSV；维度计数现算、可复算，不目测。
6. **深读代表样本**：优先选高互动/精华帖，用 `topicDetail` 精读，**单批 ≤2–3 个、拿到当轮立即落盘或提炼**；读取顺序 `aiSummaryContent` → `articleContentContainFeishuDoc` → `articleContent`。
7. **综合与溯源**：只基于已读证据下结论，区分事实/观点/一方声称；每个结论附 `scys.com/articleDetail/xq_topic/<id>` 原文链接；数字来自帖子或可复算，否则标「待核实」。
8. **交付归档**：按任务形态产出；属可复用成果时按全局归档规则询问是否入飞书知识库。

## 5. 避坑、限流与写操作红线

- **结果过大当场过期**：一次并行拉多页 contentSearch、或单轮堆多个大 topicDetail，易返回 `[Tool result expired]` 丢失。对策：分批、单批小、当轮落盘。
- **大结果会被自动持久化成 txt**：超大工具结果可能落盘为文件，用脚本解析文件而不是等正文回显。
- **深读单批 ≤2–3 个**：topicDetail 一次别超过 3 个，长文优先读 AI 摘要。
- **schema 不在上下文就先 tool_search**：连接器工具的参数 schema 被压缩/不确定时，先按精确工具名取回真实 schema 再调，不凭工具名猜参数。
- **限流约 40 次/分钟/账号**：大批量任务自行加间隔、不要开过多并行；触发限流就退避，不硬刷。
- **数据有同步延迟**：「全部帖子」等可能停在前一天，属正常，不当成漏抓。
- **只看得到权限内内容**：未加入/未购买的深海圈、航海手册取不到，不是 bug。
- **默认只读**：不被明确要求就不执行点赞/收藏/投锚/关注；批量写操作先列清单给用户确认。投锚消耗鱼丸且每日有上限；一切写操作以用户真实身份生效。
- **只走官方 MCP**：官方 OAuth 接口不会封号；不要改用浏览器插件或模拟点击爬站（有圈友因此被封）。
- 抓取/调用失败、为空要如实报告，不用旧快照或臆测填充（与 SKILL.md 溯源硬规则一致）。

## 6. AI 亦仁：事实归检索、观点归亦仁

`startAiYiRenChat`（发起）+`queryAiYiRenChat`（轮询，约几十秒，靠会话 ID 连续追问）最特殊：常规工具是豆包自己取数自己写；AI 亦仁是把问题发给生财服务器上的「亦仁数字分身」，由远端模型产出**主观判断**，豆包只转述。它**不主动翻全库**，背景要自己给足，结果是数字人观点、不是本人、需自甄别。

- 常规检索回答「有什么/是什么/谁做过/原文怎么说」（事实、资料、数据，可逐条核对）。
- AI 亦仁回答「怎么看/该不该/值不值/先做什么」（判断、取舍、泼冷水）。
- **必须显式点名「问 AI 亦仁」**，否则可能被默认走成常规检索；问题应是判断题而非查资料题。
- 最佳配合：① 先用常规工具把事实和链接捞全 → ② 让豆包基于材料出一版方案 → ③ 再交 AI 亦仁做决策批判，最后用户拍板。

## 7. 提问句式与完整案例

**常规检索万能句式**：「用 scys-mcp 先去生财搜【主题】的高赞精华帖/项目库案例/航海手册，读 X 篇，再结合我的情况【…】帮我【写/评估/定方案】，每个结论附原文链接，全程只读。」

**AI 亦仁三句式**：
1. 项目判断：「问 AI 亦仁：我的情况是【背景/资源/约束】，打算做【方案】，你怎么看？我哪里还没想清楚？」
2. 方案挑错：「把这份计划发给 AI 亦仁，让他以老板视角挑毛病、泼冷水，再反问我三个关键问题。」
3. 方向取舍：「让 AI 亦仁判断 A、B 两条路，以我【时间/资金/能力】优先押哪个，为什么？」

**完整案例（通用管线复盘，2026-09，验证本通道可支撑中大型主题调研）**：对某消费赛道做一次社区普查——contentSearch 翻 12 页（pageSize=50）加 searchTopic 兜底 → 按 entityId 去重得 548 篇 → 标题相关性过滤并人工救回边界项后留 174 篇 → 规则脚本打 7 维标签导出多维 CSV、计数现算 → topicDetail 深读 9 篇高互动精华（优先 AI 摘要与飞书全文，单批≤3、当轮落盘）→ 产出行业报告（HTML/PDF）、可检索知识库与多维分类 CSV，每条结论可回源原文。
可复用经验：① 去重与过滤前后都要留量级，证明样本怎么来的；② 深读优先 `aiSummaryContent` 能大幅省 token；③ 严格单批≤3、当轮落盘可规避结果过期；④ 站内垂直方向若基本无帖（如某冷门 ToP 领域），尽快判定为死路、换关键词或换通道，不反复空转。
