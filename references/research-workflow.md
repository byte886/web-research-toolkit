# 调研标准作业流程（research-workflow）

> 把"查资料"变成可复现、可溯源的工程。配合 `channel-selection.md`（选通道）与 `source-schema.md`（结构化与溯源）使用。

## 目录
1. 七步 SOP 详解
2. 信源策略与交叉核验
3. 反幻觉与不确定性清单
4. 房地产评估调研专项清单
5. 交付与归档

---

## 1. 七步 SOP 详解

### 步骤 1：界定问题与交付物
- 用一句话写清调研目标；拆成可独立回答的子问题清单。
- 明确交付物：一段结论 / 对比表 / 结构化数据集 / 完整报告；明确地域、时间范围、口径。
- 明确"够用标准"：多少来源、多少样本即可支撑结论，避免无限采集。

### 步骤 2：拆子问题、列信源清单
- 为每个子问题先列"理想信源"（谁是一手权威），再列备选源。
- 信源优先级：官方/一手 > 权威机构/统计 > 行业专业源 > 二手汇编 > 自媒体（分级见 source-schema）。
- 形成"子问题 × 候选源 × 通道"的采集计划小表。

### 步骤 3：选通道采集
- 按 channel-selection 决策树选通道；先广搜定位 URL，再 web.fetch 精读或 Firecrawl 批量抓取。
- 边采边记：每条立即记 sourceUrl、来源名、抓取时间，不要事后补。
- 批量任务先小样本试跑（如先抓 3–5 页验证字段质量），再放量，省 credit、防系统性错误。

### 步骤 4：去重与交叉核验
- 按标题/URL/稳定 ID 去重；同一事实多页面转载要追溯到最初源头。
- 关键事实 ≥2 个独立来源一致才作为"已查证"；不一致则并列保留并标注分歧。
- 明确区分：**事实（可验证）/ 观点（某人认为）/ 一方声称（利益相关方说法）**。

### 步骤 5：结构化
- 用固定 schema 落表，字段定义一次写清、全程一致；模板见 source-schema。
- 数值统一单位与口径（万元/元、㎡/亩、容积率、日期 YYYY-MM-DD），换算用计算工具现算并保留原值。
- 每条必带溯源四字段：sourceUrl、sourceName、sourceTier、fetchedAt。

### 步骤 6：综合分析
- 只基于已核验证据推理；用证据支撑每个结论，结论与证据可互相跳转。
- 证据不足以下结论时，明确写"待核实/缺什么"，不用常识或旧印象补。
- 定量结论给出口径、样本量、时间窗；区分趋势、相关与因果。

### 步骤 7：交付与归档
- 交付物中关键论断后附来源链接；列出已查证 vs 一方称 vs 未核实。
- 说明采集方式、覆盖范围、样本数与已知缺口（哪些没抓到、为什么）。
- 有复用价值的数据集/方法沉淀到项目目录或飞书知识库（按项目规则先询问用户）。

## 2. 信源策略与交叉核验

- **一手优先**：法律法规要原文（法规库/政府公报）、成交数据要交易平台原始公告、统计要统计局原表，不依赖转述。
- **交叉验证矩阵**：对每个关键结论记录"来源 A 说 / 来源 B 说 / 是否一致 / 采信谁及理由"。
- **时间一致性**：优先最新有效版本；政策注意生效/废止日期，标注"截至 YYYY-MM-DD"。
- **利益相关识别**：厂商、中介、营销稿的数据是"一方称"，需独立来源佐证。
- **无法打开/付费墙**：如实标注"未能获取原文"，不据摘要做强结论。

## 3. 反幻觉与不确定性清单（交付前逐条自检）

- [ ] 每个数字/日期/名称都有来源或可复现计算，无凭空生成。
- [ ] 没有编造的 URL、机构、文件名、统计值；链接真实可打开。
- [ ] 估算值明确标"估算"并写口径；缺数据标"待核实"而非脑补。
- [ ] 抓取失败、空页、被反爬、样本偏差已在交付物中说明。
- [ ] 事实/观点/一方声称已区分；分歧未被强行抹平。
- [ ] 结构化记录溯源四字段齐全，可回源。

## 4. 房地产评估调研专项清单

**A. 区域与市场背景（比较法/假设开发法通用）**
- 区位规划：城市总体规划、控规、城市更新/片区批复（自规局/政府公报）。
- 宏观与区域数据：人口、产业、GDP、房价指数、供地计划（统计局/住建/自规）。
- 配套：交通、教育、商业、公共设施的规划与落地时间。

**B. 交易案例（比较法核心，用 Firecrawl 建结构化库）**
- 土地成交：中国土地市场网、公共资源交易中心——地块编号、位置、用途、面积、容积率、成交价、**楼面价（可由成交价/计容建面现算并保留原值）**、竞得人、成交日期。
- 房产成交/挂牌：选可比案例时记录楼层、朝向、面积、装修、成交/挂牌时间、价格类型。
- 可比性标注：与标的的距离、时间差、用途/容积率差异，便于后续修正。

**C. 政策与参数依据**
- 基准地价、标定地价、税费、出让政策、补偿标准的**现行有效版本与文号**；权威库清单、五级分层找法、北大法宝/人民数据库分工见 `policy-source-map.md`。
- 用"关键词 + 发文字号〔〕"定位线索，回官方库或北大法宝（pkulaw 技能）取原文并核时效（现行/修订/废止），不直接引用搜索摘要。
- 造价/重置价格、资本化率等参数的来源与取值依据。

**D. 动态监测（需 Firecrawl key + Monitor）**
- 盯目标板块挂牌价/量变化、新成交公告、政策更新；字段级 diff，new/changed/gone 分类。

**E. 执业留痕**
- 每个取值可回源（sourceUrl + fetchedAt），抽样人工复核；评估报告中的数据与案例库一一对应。

## 5. 交付与归档

- 数据集默认存本地项目目录（CSV/JSON + 来源列），命名含日期与范围；过程临时文件及时清理。
- 需要团队复用/长期沉淀时，按项目 AGENTS 规则询问是否归档飞书知识库，并在归档文档中保留采集口径与来源。
- 一次调研结束沉淀"踩坑/站点可抓性"到 `channel-selection.md` 第 5 节，形成集体记忆。
